# Home 퀵슬롯·확장 검색 시각 QA

최종 점검: 2026-07-18  
범위: Home 퀵슬롯, 돋보기 확장 검색, 검색 결과/기능 추가 팝오버, 빈 `＋` 슬롯, 데스크톱·태블릿·모바일 반응형  
검토 파일: `assets/presence-home-quickslots.js`, `assets/presence-avatar-studio.css`, `index.html`의 기존 전역 검색

## 목표 인터랙션

Home에는 항상 큰 검색창을 노출하지 않는다. 기본 상태는 정돈된 퀵슬롯과 작은 돋보기만 보여주고, 사용자가 돋보기를 눌렀을 때 검색 입력이 자연스럽게 확장된다. 검색 결과와 `＋` 기능 선택은 해당 컨트롤 아래에 붙는 팝오버로 열리며, 모바일에서는 하단 안전영역 위의 바텀시트로 전환한다.

권장 흐름은 다음과 같다.

1. **기본:** 등록된 퀵슬롯 + 동일 크기의 빈 `＋` 슬롯 + 돋보기 버튼.
2. **검색 열기:** 돋보기가 검색창으로 확장되고 커서가 즉시 입력칸에 간다.
3. **결과 보기:** 검색창 바로 아래 팝오버에 기능·팀원·자료 결과가 나타난다.
4. **기능 추가:** 빈 `＋` 슬롯을 누르면 같은 위치의 하단 팝오버에 추가 가능한 기능만 나타난다.
5. **선택 완료:** 기능을 선택하면 팝오버가 닫히고 새 퀵슬롯이 `＋` 자리 앞에 추가된다.
6. **닫기:** 바깥 클릭, `Esc`, 뒤로가기, 다른 탭 이동 시 검색/팝오버가 모두 닫힌다.

## 구성 원칙

- 돋보기와 `＋`는 의미가 다른 두 버튼이며, `⌘`, 점 세 개, 추상 기호로 대체하지 않는다.
- `＋`는 별도 긴 문장 버튼이 아니라 다른 퀵슬롯과 같은 너비·높이·모서리를 가진 빈 슬롯이다.
- 검색 결과와 기능 선택은 서로 다른 전체 화면 모달을 만들지 않고 하나의 팝오버 셸을 재사용한다.
- 퀵슬롯 이름 길이가 달라도 카드 폭·높이·아이콘 위치가 같아야 한다.
- 팝오버는 Home 콘텐츠를 밀지 않고 위에 뜨되, 헤더·하단 내비게이션·알림·더보기 메뉴와 겹치지 않는다.
- 편집용 이동·삭제는 기본 화면에 노출하지 않고 편집 모드에서만 44px 이상의 명확한 버튼으로 제공한다.

## 반응형 규격

### 데스크톱 — 1200px 이상

- 퀵슬롯 영역은 Home 본문 폭 안에서 한 카드로 정렬한다.
- 슬롯은 4열 그리드, 최대 8개는 2행으로 배치한다.
- 돋보기는 44×44px이며 슬롯 행의 오른쪽 기준선에 맞춘다.
- 검색 확장 폭은 360~480px, 높이는 44~48px다.
- 결과 팝오버는 검색창 바로 아래 8px 간격으로 열고 검색창 오른쪽 또는 퀵슬롯 카드 오른쪽과 정렬한다.
- 팝오버 너비는 검색창과 같거나 최대 520px, 높이는 최대 420px다.
- 팝오버가 열려도 Home 타이틀과 첫 콘텐츠를 가리지 않아야 한다.

### 태블릿 — 768~1199px

- 슬롯은 3열 또는 4열 중 최소 카드 폭 160px을 만족하는 쪽을 사용한다.
- 돋보기 클릭 시 검색창은 슬롯 영역의 한 행 전체 폭으로 확장한다.
- 결과 팝오버는 퀵슬롯 카드 좌우 패딩 안에서 전체 폭으로 열고 최대 높이 45vh를 넘지 않는다.
- 세로 태블릿에서 팝오버 하단이 화면 밖으로 밀리면 위로 열지 말고 내부 스크롤을 사용한다.
- 터치 대상은 모두 최소 44×44px이다.

### 모바일 — 767px 이하

- 슬롯은 2열 그리드, 360px 이하에서도 각 슬롯의 최소 폭 144px을 확보한다.
- 기본 돋보기와 빈 `＋` 슬롯은 최소 48px 높이로 표시한다.
- 검색을 열면 돋보기는 48px 높이의 전체 폭 검색창으로 전환하고, 별도의 닫기 버튼을 제공한다.
- 검색 결과/기능 선택은 화면 하단 바텀시트로 열며 `bottom: calc(하단 내비 높이 + env(safe-area-inset-bottom))`을 따른다.
- 바텀시트는 화면 좌우 8~12px 여백, 최대 높이 60dvh, 내부 스크롤을 사용한다.
- 키보드가 열리면 입력창과 첫 결과가 보이고, 하단 내비게이션과 겹치지 않아야 한다.
- 390×844, 430×932, 360×800에서 가로 스크롤이 없어야 한다.

## 현재 구현의 실패 목록

### P0 — 구조 충돌

1. **검색 UI가 두 벌이다.**  
   `presence-home-quickslots.js`는 Home 최상단에 항상 보이는 검색 입력과 `⌕` 버튼을 만들고, `index.html`은 별도의 고정 `🔎` 버튼과 전역 검색 모달을 항상 노출한다. 한 화면에 검색 진입점이 중복되어 사용자가 무엇을 눌러야 할지 모른다.

2. **현재 검색은 확장이 아니라 전체 화면 모달 전환이다.**  
   퀵슬롯 검색은 `runHomeQuickSearch()`에서 `hsOpen()`을 호출해 Home 밖의 `.hs-modal`을 연다. 검색창 아래 팝오버라는 공간 맥락이 끊긴다.

3. **기능 추가가 하단 팝오버가 아닌 전체 화면 모달이다.**  
   `.quickslot-modal`은 `position:fixed; inset:0` 전체 오버레이이며 검색 모달과도 별개 디자인이다. 요청한 한 셸 기반의 하단 팝오버 구조가 아니다.

4. **고정 검색 버튼의 위치 규칙이 충돌한다.**  
   기본 CSS는 `top:76px`, 모바일은 `top:66px`을 지정하지만 후속 모바일 CSS는 `bottom:calc(86px + safe-area)`도 추가하면서 `top:auto`로 해제하지 않는다. 같은 요소에 위·아래 위치가 동시에 남아 기기별 간섭 가능성이 높다.

### P1 — 대칭·반응형·사용성

5. **슬롯이 그리드가 아니라 가변 폭 flex다.**  
   `.hqd-slots{display:flex; flex-wrap:wrap}`과 라벨 기반 자동 폭 때문에 슬롯마다 길이가 다르고 마지막 행 정렬이 깨진다.

6. **빈 `＋` 슬롯이 다른 슬롯과 모양이 다르다.**  
   현재는 `＋ 기능 추가`라는 긴 점선 알약 버튼이다. 빈 슬롯이 아니라 별도 CTA처럼 보여 퀵슬롯 체계가 비대칭이다.

7. **큰 카드가 Home 첫 화면을 과도하게 밀어낸다.**  
   제목, 설명, 편집, 상시 검색창, 빈 문장, 추가 버튼까지 모두 `#m-home .wrap` 첫 자식으로 삽입된다. 기존 Hero보다 앞서면서 Home의 핵심 인상과 콘텐츠 우선순위를 바꾼다.

8. **다른 동적 홈 카드와 삽입 순서가 경쟁한다.**  
   퀵슬롯과 행사 응답 카드 모두 `host.firstChild` 앞에 자신을 삽입한다. 로딩 순서에 따라 어느 카드가 위에 놓일지 달라져 첫 화면이 흔들릴 수 있다.

9. **편집 액션이 지나치게 작고 비대칭이다.**  
   이동/삭제가 21×21px `i` 요소 세 개로 표시된다. 터치 기준 44px에 못 미치며 실제 버튼도 아니어서 키보드 접근이 어렵다.

10. **모바일은 팝오버가 아닌 92vw 상단 모달이다.**  
    `.hs-box`는 `margin:12vh auto 0`, 기능 추가 모달은 화면 중앙 배치다. 모바일 하단 바텀시트와 키보드 회피 규칙이 없다.

11. **모바일에도 검색 진입점이 중복된다.**  
    Home 카드의 상시 입력창과 52px 고정 검색 버튼이 동시에 존재하며, 고정 버튼은 헤더/하단 내비게이션/허브 귀환 FAB와 겹칠 수 있다.

12. **접근성 상태가 없다.**  
    검색·추가 트리거에 `aria-expanded`/`aria-controls`가 없고 기능 추가 모달은 `role=dialog`, `aria-modal`, 포커스 트랩, `Esc` 닫기가 없다.
