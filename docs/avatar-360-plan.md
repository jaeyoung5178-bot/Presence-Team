# Presence Avatar Studio — 진짜 360° 코디 뷰어 계획

최종 갱신: 2026-07-18  
범위: 조사·자산 계약·상태·UX·접근성·단계별 출시 계획. 이 문서는 구현 코드를 포함하지 않는다.

## 결론

현재 Avatar Studio는 **정면 2D 레이어 합성기**다. 각 자산은 하나의 418×418 정면 캔버스만 가지며, 후면·측면·회전 프레임 또는 3D 메시가 없다. 따라서 지금 상태에서 `scaleX(-1)`, `rotateY()`, 원근 왜곡을 붙이는 것은 회전처럼 보이게 만드는 가짜 효과일 뿐이다. 특히 백팩과 케이프의 실제 뒷모습, 몸에 가려지는 부분, 어깨끈을 올바르게 표현할 수 없다.

Presence의 현재 회화적 화풍을 유지하면서 가장 빨리 품질을 확보하는 최소 방식은 **각 각도를 따로 제작한 16방향 2D 턴테이블**이다. 마우스나 손가락으로 부드럽게 드래그하되 화면은 22.5°마다 제작된 실제 정면·측면·후면 프레임으로 전환한다. 프레임 사이에 CSS로 이미지를 찌그러뜨리거나 반전하지 않는다.

장기적으로 모든 코스튬을 자유 조합하려면 3D 원본(glTF/메시·리깅·재질) 체계가 더 확장성이 높다. 그러나 현재 자산에는 3D 원본이 없고, 3D 재제작 시 지금의 털 질감과 얼굴 인상을 잃을 위험이 크다. 그러므로 **16방향 2D로 품질 기준과 UX를 먼저 확정한 뒤, 3D 전환 여부를 판단**한다.

## 현재 저장소 조사 결과

조사 위치:

- `assets/pets/`
- `assets/presence-avatar-studio.js`
- `assets/presence-avatar-studio.css`
- `scripts/build-avatar-assets.py`
- `scripts/build-accessory-assets.py`
- `docs/DESIGN_QUALITY_GUARDRAILS.md`

### 파일과 렌더링 구조

- `assets/pets/`에는 총 176개 파일, 약 24MB가 있다.
- 이름 기준 분류는 PNG 100개, WebP 76개다. 다수는 동일 그림의 PNG/WebP 중복 또는 아이콘·알파 중간 산출물이다.
- 바디 컬러: 12색의 PNG/WebP 쌍(`presence-base-*`).
- 털 모양: 8종의 PNG/WebP 쌍(`presence-feather-*`).
- 액세서리: 16종의 PNG/WebP 쌍(`presence-accessory-*`).
- 의상·머리·소품 아이템: 정면 자산 9종의 PNG/WebP 쌍(`presence-item-*`).
- 의상 4종 × 머리 3종의 완성 착장 조합 WebP가 존재하고, PNG·알파 작업본도 일부 존재한다(`presence-fitted-*`).
- 모든 실제 레이어는 공통 418×418 좌표계에 맞춘 정면 이미지다. `back`, `rear`, `side`, `angle`, `frame`, `360` 이름의 시점 자산은 하나도 없다.
- 카탈로그의 172개 노출 항목은 172개의 서로 다른 형태가 아니다. 약 25개의 정면 형태 자산에 `hue-rotate`, 채도, 밝기 등의 필터 변형을 곱한 SKU다.

### 현재 코드에서 확인된 한계

- `art()`는 `back → base/master → tone → feather/body/head → accessory` 순서의 정면 z-index 합성만 한다.
- `pgp-back`은 항상 캐릭터 본체 뒤(z-index 0)에 놓인다. 시점에 따른 깊이 순서 전환이 없다.
- `presence-accessory-backpack.png`는 가방 본체와 병아리 날개가 한 장에 포함된 정면형 합성 자산이다. 별도의 뒤판, 어깨끈, 가림 마스크가 없다.
- 케이프도 한 장의 정면형 레이어이며 후면 실루엣이 없다.
- 완성 착장 마스터는 얼굴·의상 일체감을 지키는 좋은 정책이지만, 역시 정면 한 장뿐이다.
- CSS는 모든 이미지에 `transform:none!important`를 사용한다. 회전 상태·드래그·포인터 캡처·키보드 각도 조작도 없다.
- 아바타 설정은 `presence_pet_<uid>` 및 `petProfiles/<uid>`에 저장되지만, 뷰 각도나 자산 지원 수준을 표현하는 상태는 없다.

### 품질 판정

현재 자산은 **정면 코디에는 사용 가능**하지만 **360°에는 사용 불가**다. 기존 백팩 이미지를 뒤에서 보는 장면으로 재사용하거나 좌우 반전하는 것도 금지한다. 가방 표면은 보일 수 있어도 캐릭터의 등·목·꼬리·날개와의 가림 관계가 틀리고, 사용자가 기대하는 “착용한 뒤태”가 아니다.

## 구현 방식 결정

| 방식 | 진짜 후면 | 현재 화풍 보존 | 조합 확장성 | 초기 비용 | 결정 |
|---|---:|---:|---:|---:|---|
| CSS `rotateY`/좌우 반전 | 아니오 | 낮음 | 낮음 | 낮음 | 금지 |
| 정면 그림을 메시처럼 휘기 | 아니오 | 낮음 | 낮음 | 중간 | 금지 |
| 각도별 2D 턴테이블 | 예 | 높음 | 중간 | 중간 | 최소 출시안 |
| 실시간 3D glTF | 예 | 재현에 따라 다름 | 높음 | 매우 높음 | 장기 검토 |

### 최소 출시안: 16방향 2D 턴테이블

- 각 프레임은 22.5° 간격의 실제로 제작·검수된 그림이다.
- 기준 각도: 정면 0°, 우전면 45°, 오른쪽 90°, 우후면 135°, 후면 180°, 좌후면 225°, 왼쪽 270°, 좌전면 315°를 포함한다.
- 16방향이 모두 준비되기 전 제작 중간 검수는 8방향으로 해도 되지만, 사용자에게 “360°”로 공개하는 기준은 16방향 전체 통과다.
- 드래그 이동량을 누적 각도로 바꾸고 가장 가까운 제작 프레임을 표시한다. 프레임 자체에는 2D/3D transform을 적용하지 않는다.
- 빠른 드래그에는 짧은 관성 이동을 허용하되, 마지막에는 정확한 프레임 각도에 스냅한다.
- 자동 회전은 기본 꺼짐이다. 사용자가 재생 버튼을 눌렀을 때만 작동하고 포커스·드래그·페이지 비가시 상태에서 즉시 멈춘다.

### 왜 8방향이 아닌 16방향인가

8방향(45° 간격)은 백팩 측면 두께와 어깨끈이 갑자기 튀는 느낌이 강하다. 스테이지가 최대 약 410px이고 현재 캐릭터가 비교적 사실적인 질감이므로 전환이 더 눈에 띈다. 16방향은 모바일 다운로드와 제작량을 통제하면서도 드래그가 회전에 가깝게 느껴지는 하한선이다. 24방향은 2차 개선 후보로 둔다.

## 360° 자산 계약

### 단일 기준 좌표계

- 제작 기준 캔버스: 768×768 투명 RGBA 권장, UI에는 최대 1×/2×로 내려서 제공한다.
- 모든 각도에서 발의 중심, 지면 높이, 캐릭터의 질량 중심, 카메라 높이, 초점 거리, 광원 방향을 고정한다.
- 회전축은 캔버스 중심이 아니라 실제 양발 사이의 수직축으로 정의한다.
- 모든 자산은 동일한 `rigVersion`과 `cameraVersion`을 가져야 조합 가능하다.
- 후면에서도 털 흐름, 볏의 기울기, 날개 관절, 발 방향이 앞면과 연속적이어야 한다.

### 권장 파일 구조

```text
assets/pets/turntable/
  manifest.v1.json
  chick-base/
    atlas-00.webp        # 16프레임 4×4 아틀라스
    body-mask.webp       # 색상 변경용 각도별 마스크
  feather-classic/
    atlas-00.webp
  back-backpack/
    under.webp           # 몸 뒤에 가려지는 가방 본체
    over.webp            # 앞에서 보이는 끈/버클/접촉부
    occlusion.webp       # 필요 시 몸/의상 가림 마스크
  back-cape/
    under.webp
    over.webp
    occlusion.webp
```

실제 파일명은 바꿀 수 있지만, **각도별 파일 존재 여부와 합성 계약을 manifest가 단일 진실 공급원으로 가져야 한다.** 파일명 추측으로 지원 수준을 결정하지 않는다.

### manifest 필수 필드

```json
{
  "schemaVersion": 1,
  "rigVersion": "chick-rig-1",
  "cameraVersion": "turntable-ortho-1",
  "frameCount": 16,
  "angles": [0, 22.5, 45, 67.5, 90, 112.5, 135, 157.5, 180, 202.5, 225, 247.5, 270, 292.5, 315, 337.5],
  "items": {
    "back_backpack_0": {
      "viewTier": "turntable-16",
      "underAtlas": "back-backpack/under.webp",
      "overAtlas": "back-backpack/over.webp",
      "rigVersion": "chick-rig-1",
      "testedWith": ["base_default"]
    }
  }
}
```

### 백팩·케이프에 특별히 필요한 자산

백팩은 한 장으로 만들면 안 된다. 최소한 다음이 각 16각도로 필요하다.

- 가방 본체와 등 뒤 파트(`under`)
- 가슴/어깨 앞으로 넘어오는 끈, 버클, 날개와 만나는 접촉부(`over`)
- 몸·의상에 의해 가려지는 영역을 위한 마스크
- 오른쪽/왼쪽 측면에서 보이는 실제 두께
- 후면의 가방 앞판, 포켓, 윗손잡이와 캐릭터의 뒤통수·날개·발
- 의상 두께가 달라질 때 끈이 파묻히거나 뜨지 않는 fit 변형 또는 호환 목록

케이프도 목 고리와 앞쪽 매듭은 `over`, 천의 대부분은 `under`로 분리한다. 후면에서는 천이 본체 앞에 보일 수 있으므로 각도별 깊이 규칙을 manifest에 둔다. 바람에 펄럭이는 애니메이션은 360°가 안정된 뒤 별도 기능으로 다룬다.

### 색상과 털 모양

- 바디 12색은 단순 CSS `mix-blend-mode`가 아니라 각도별 바디 마스크와 명도 보존 LUT/재색상 파이프라인으로 만든다.
- 눈, 부리, 볏, 발, 하이라이트는 색상 마스크에서 제외한다.
- 털 모양 8종은 정면 머리 장식이 아니라 뒤통수 실루엣까지 포함한 16각도 자산이어야 한다.
- 완성 착장 마스터를 쓰는 조합은 각도마다 얼굴·의상·날개가 통합된 완성 마스터가 필요하다. 정면 마스터와 각도별 분리 레이어를 섞지 않는다.

## 상태 모델

### 저장 상태와 일시 상태를 분리

기존 사용자 프로필은 유지한다.

```text
저장/동기화:
  color
  feather
  equipped[slot]
  presetIds (추가 단계)

스테이지에서만 사용하고 서버에는 저장하지 않음:
  yaw                 0..359.999
  frameIndex          0..15
  dragging
  activePointerId
  velocity
  autoRotate
  zoom                1.0 (최소 출시에서는 고정 가능)
  viewTier            turntable-16 | rear-pair | front-only
  lastGoodFrame
  loading/error assets
```

사용자가 아바타를 저장하는 것과 카메라를 돌려 보는 것은 다른 행위다. `yaw`를 `petProfiles`에 저장하면 다른 화면의 축소 아바타가 우연히 뒤를 보는 부작용이 생기므로 저장하지 않는다. Studio를 다시 열 때는 기본 정면으로 시작하되, 같은 열림 세션 안에서는 마지막 각도를 유지한다.

### 렌더러 입력

```text
AvatarAppearance + ViewState + CapabilityManifest
  → 조합 호환성 판정
  → viewTier 결정
  → 필요한 각도 프레임 로드
  → 각도별 z-order/occlusion 합성
  → 접근 가능한 현재 모습 설명 갱신
```

아이템을 선택할 때 기존 `render()`로 스테이지 DOM 전체를 교체하면 드래그 상태와 포커스가 끊긴다. 스테이지 컨트롤러는 한 번 마운트하고 appearance만 갱신하는 구조로 분리해야 한다.

## 드래그·마우스 UX

### 기본 동작

- 스테이지에 진입하면 “좌우로 드래그해 회전” 힌트를 한 번만 보여준다.
- 포인터를 누른 위치를 기준으로 수평 6~10px 이상 이동했을 때 회전을 시작한다. 단순 탭/클릭은 회전으로 오인하지 않는다.
- 데스크톱 권장 감도: 스테이지 폭의 약 0.9배 드래그 = 360°. 사용자 테스트로 0.75~1.25배 범위에서 조정한다.
- 드래그 중 `setPointerCapture()`를 사용해 포인터가 스테이지 밖으로 나가도 회전을 이어간다.
- `pointerup`, `pointercancel`, 창 포커스 상실 때 반드시 캡처와 dragging 상태를 정리한다.
- 렌더링은 `requestAnimationFrame`당 최대 한 번만 한다. 포인터 이벤트마다 DOM을 재생성하지 않는다.
- 커서는 대기 시 `grab`, 드래그 시 `grabbing`이다.
- 더블클릭은 정면 0°로 돌아오기, 전면/후면 버튼은 각각 0°/180°로 이동한다.

### 명시적 컨트롤

드래그만 제공하면 발견성과 접근성이 낮다. 스테이지 아래에 다음을 항상 둔다.

- `앞` 버튼
- `뒤` 버튼
- `왼쪽 각도` / `오른쪽 각도` 버튼
- `자동 회전 시작/정지` 버튼(최소 출시에서 생략 가능)
- 현재 방향 텍스트: `정면`, `오른쪽`, `후면`, `왼쪽` 및 중간 방향

백팩 카테고리를 선택하거나 백팩을 착용하면 최초 1회 후면 180°로 자연스럽게 이동해 실제 착용 모습을 바로 확인시킨다. 이후 사용자가 직접 돌린 각도는 존중하고 자동으로 반복 전환하지 않는다.

## 모바일 제스처

- Pointer Events 하나로 마우스·펜·터치를 통합한다.
- 스테이지는 `touch-action: pan-y pinch-zoom`을 사용한다. 가로 드래그는 회전, 세로 드래그는 페이지 스크롤, 두 손가락은 브라우저 확대를 우선한다.
- 처음 8~12px 이동에서 수평/수직 의도를 판별한다. 수직 의도면 포인터를 가로채지 않는다.
- 스크롤 중 캐릭터가 우연히 돌아가지 않도록 수평 우세 비율(예: `abs(dx) > 1.25 * abs(dy)`)을 둔다.
- 회전 조작 영역과 모든 보조 버튼의 터치 타깃은 최소 44×44px로 한다.
- iOS에서 스테이지 가장자리의 뒤로가기 제스처와 충돌하지 않도록 화면 좌우 가장자리 20px 안에서 시작된 포인터는 회전을 시작하지 않는다.
- 최소 출시에서는 핀치로 캐릭터 자체를 확대하지 않는다. 브라우저 확대를 막지 않는 편이 접근성에 낫다. 캐릭터 줌은 후속 단계에서 별도의 `+/-` 버튼과 함께 제공한다.
- 한 손가락 관성은 최대 300~450ms로 짧게 제한한다. `prefers-reduced-motion`이면 관성과 자동 회전을 끈다.

## 접근성

### 키보드

스테이지 옆에 시각적으로 보이는 각도 슬라이더 또는 동일 기능의 각도 컨트롤을 둔다.

- `Left` / `Right`: 한 프레임(22.5°) 회전
- `Shift + Left` / `Shift + Right`: 90° 회전
- `Home`: 정면 0°
- `End`: 후면 180°
- `Space`: 자동 회전 시작/정지 버튼에 포커스가 있을 때만 작동
- 포커스 링을 항상 명확히 표시하고, 선택 상태와 키보드 포커스를 구분한다.

각도 슬라이더를 쓸 경우 `role="slider"`, `aria-valuemin="0"`, `aria-valuemax="15"`, `aria-valuenow`, `aria-valuetext="후면, 180도"`를 갱신한다. WAI-ARIA APG의 Slider Pattern을 따른다. 터치 보조기술에서 커스텀 슬라이더 제스처 지원이 불완전할 수 있으므로 `앞/뒤/이전/다음` 네 개의 네이티브 버튼을 반드시 함께 제공한다.

### 스크린리더와 알림

- 스테이지 wrapper는 `aria-labelledby`로 아바타 이름과 연결한다.
- 캔버스/스프라이트 내부 장식 이미지는 `alt=""`로 두고 중복 낭독을 막는다.
- 별도의 상태 텍스트에 `현재 후면. 익스플로러 백팩, 리더 재킷, 밀짚모자 착용.`처럼 현재 방향과 핵심 착장을 제공한다.
- 드래그 중 16번 모두 읽지 않는다. 포인터를 놓거나 키보드 스냅이 끝난 뒤에만 `aria-live="polite"`로 최종 방향을 알린다.
- 아이템 버튼은 `aria-pressed`로 착용 여부를 알리고, 색상·털 선택은 라디오 그룹 패턴을 쓴다.
- 자동 회전은 기본 꺼짐이며 키보드 포커스가 스테이지에 들어오면 멈춘다.

### 시각·모션

- 방향은 색만으로 표시하지 않고 텍스트와 선택 표식을 함께 쓴다.
- 드래그 힌트, 로딩, 정면 전용 배지는 WCAG 대비를 확인한다.
- `prefers-reduced-motion: reduce`에서는 자동 회전·관성·스냅 애니메이션을 제거하고 즉시 프레임을 바꾼다.
- 확대/고대비 모드에서 컨트롤이 캐릭터를 가리거나 잘리지 않아야 한다.

참고: [W3C APG Slider Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/slider/), [W3C Keyboard Interface Practice](https://www.w3.org/WAI/ARIA/apg/practices/keyboard-interface/), [MDN Pointer Events](https://developer.mozilla.org/en-US/docs/Web/API/Pointer_events)

## 폴백 기준

### 지원 등급

| 등급 | 조건 | 사용자 경험 |
|---|---|---|
| `turntable-16` | 모든 16각도, 마스크, z-order, 시각 QA 통과 | 드래그 360°, 앞/뒤/각도 버튼 모두 사용 |
| `rear-pair` | 정면·후면 두 장만 검수 | `앞/뒤` 전환만 제공, 360°라고 부르지 않음 |
| `front-only` | 기존 정면 자산만 있음 | 정면 고정, “정면 미리보기” 배지 |
| `blocked` | 깨진 알파·잘못된 rig·누락 프레임 | 인벤토리와 출시 목록에서 숨김 |

### 조합 판정

- 현재 착장에 포함된 **모든 보이는 슬롯의 최저 등급**이 전체 스테이지 등급이다.
- 16프레임 중 하나라도 없거나 크기·회전축 검사가 실패하면 `turntable-16` 자격을 잃는다.
- 서로 다른 `rigVersion` 또는 `cameraVersion`을 섞지 않는다.
- 후면 지원 아이템과 정면 전용 아이템을 함께 착용하면 전체 스테이지는 `front-only`가 된다. 지원하지 않는 아이템을 후면에서 숨기거나 앞면 그림을 뒤집어 보여주지 않는다.
- 사용자가 후면을 보고 있을 때 정면 전용 아이템을 착용하면 정면으로 전환하고 “이 아이템은 현재 정면 미리보기만 지원해요”를 한 번 안내한다.
- 이미지 로드 실패 시 마지막으로 성공한 프레임을 유지하고, 짧은 재시도 후 정면 정적 자산으로 내려간다. 깨진 이미지 아이콘이나 빈 스테이지를 노출하지 않는다.
- 저속 네트워크에서는 정면 → 후면 → 좌우 측면 → 인접 프레임 순서로 점진 로드한다. 필요한 각도가 준비되지 않은 동안 드래그 입력은 받아도 마지막 준비 프레임을 유지하고 로딩 상태를 표시한다.
- `Save-Data` 또는 저메모리 기기에서는 8방향 경량 아틀라스를 쓸 수 있으나 UI 문구는 “360° 고화질”이 아니라 “회전 미리보기”로 구분한다.

## 최소 출시 범위(MVR)

“버튼이 있다”가 아니라 “백팩의 뒤태를 실제로 확인할 수 있다”가 완료 조건이다.

### 포함

1. 기본 병아리 1종의 16방향 베이스.
2. 기본 털 `classic`의 앞·옆·뒤 연속 실루엣.
3. 바디 컬러 3색(허니·민트·라일락)의 검수된 각도별 재색상.
4. 후면 핵심 2종:
   - 익스플로러 백팩 16방향(`under/over/occlusion`)
   - 히어로 케이프 16방향(`under/over/occlusion`)
5. 기본 무착장 + 백팩 + 케이프의 세 조합을 PC/모바일에서 드래그 회전.
6. 앞/뒤/이전/다음 버튼, 키보드 조작, 현재 방향 낭독.
7. 정면 전용 자산의 명시적 폴백과 배지.
8. 로딩·오류·저속 네트워크 폴백.

### 제외

- 기존 172개 SKU 전체의 360° 지원
- 모든 12색·8털·의상 4종·머리 3종의 완전 자유 조합
- 걷기·점프·케이프 물리·표정 애니메이션
- 핀치 캐릭터 줌, 배경 변경, 사진 저장/공유
- 실시간 3D/WebGL

MVR에서 기존 아이템을 삭제하지 않는다. 360 인증을 받지 못한 항목은 정면 코디에서 계속 사용할 수 있지만 “360° 지원” 배지는 붙이지 않는다.

## 전체 출시 단계

### 0단계 — 계약과 골든 샘플

- manifest 스키마와 16각도 제작 템플릿 확정
- 기본·백팩·케이프의 정면/측면/후면 골든 프레임 제작
- 회전축, 광원, 비율, 가림 관계를 대표 승인 후 나머지 각도 제작
- 자동 검사: 크기, 알파, frameCount, rigVersion, 빈 프레임, 아틀라스 좌표

### 1단계 — MVR

- 16방향 렌더러와 포인터 컨트롤러
- 기본 + 백팩 + 케이프
- 키보드, 스크린리더, reduced-motion, 모바일 세로 스크롤 공존
- 정면 전용 폴백

### 2단계 — 핵심 코디 확장

- 의상 4종과 머리 3종의 대표 완성 착장부터 16방향 추가
- 털 8종, 컬러 12색 확대
- 각 아이템 카드에 `360 지원` 필터/배지
- 충돌 검증을 통과한 조합만 manifest의 `testedWith`에 등록

### 3단계 — 코디 시스템 완성도

- 메이플스토리처럼 자주 쓰는 조합을 저장·적용하는 프리셋 3칸
- 현재 착장과 프리셋의 차이, 슬롯별 해제, 전체 초기화, 최근 착장 되돌리기
- “입어보기”와 “저장/적용”을 분리하여 잘못된 클릭을 되돌릴 수 있게 함
- 아이템 카테고리, 검색, 360 지원 필터, 세트 추천

메이플스토리 공식 가이드에서 참고할 핵심은 아이템 수 자체가 아니라 **코디 프리셋 3개, 드래그앤드롭 장착·해제, 현재 적용 상태의 명확한 구분**이다. Presence에는 결제/능력치 복잡성을 들이지 않고, 조합 저장과 되돌리기 경험만 차용한다. 참고: [메이플스토리 치장 아이템·코디 프리셋 가이드](https://maplestory.nexon.com/Guide/N23GameInformation/Articles/429)

### 4단계 — 3D 전환 게이트

다음 조건이 모두 맞을 때만 실시간 3D 프로토타입을 검토한다.

- 신규 아이템 제작량 때문에 16방향 자산 비용이 지속 불가능함
- 3D 골든 샘플이 현재 정면 일러스트의 얼굴·털·광원을 90점 이상 재현함
- iPhone Safari와 보급형 Android에서 로딩·메모리·발열 기준 통과
- WebGL 실패 시 동일 착장의 2D 정면 폴백 존재

## 성능 예산

- 첫 정면 프레임은 Studio 진입 후 1초 이내 표시를 목표로 한다.
- MVR 초기 필수 다운로드(기본 + 현재 장착 아이템 + 정면/후면 우선)는 압축 후 2MB 이하 목표.
- 전체 16프레임은 유휴 시간에 점진 로드하며, 현재 각도의 인접 프레임을 우선한다.
- 4×4 2048px 이하 WebP 아틀라스를 우선 검토한다. 저사양 GPU의 최대 텍스처 크기를 넘지 않는다.
- 프레임 전환 중 레이아웃 재계산 없이 background-position 또는 canvas crop만 바꾼다.
- 이미지 디코딩 완료 전 `decode()`/프리로드 상태를 확인하여 빈 프레임을 방지한다.
- 모달을 닫으면 관성·자동 회전·미완료 로드 작업을 중단한다.

## QA와 출시 게이트

### 자산 QA

- 0°와 360° 경계에서 실루엣이 튀지 않음
- 모든 프레임의 발바닥과 회전축이 고정됨
- 눈 크기, 부리 길이, 볏 개수, 날개 길이가 각도 사이에서 변형되지 않음
- 백팩 끈이 목·가슴·날개에 뜨거나 파묻히지 않음
- 후면에서 백팩 본체와 케이프가 실제로 보이며 앞면 그림의 반전 흔적이 없음
- 좌우 비대칭 디자인이 회전 방향에 맞게 유지됨
- 투명 가장자리의 녹색 halo, 사각 배경, 알파 끊김 없음

### 상호작용 QA

- 마우스, 트랙패드, 터치, 펜에서 동일한 각도 방향
- 빠른 드래그 후 캐릭터가 무한 회전하지 않음
- 세로 페이지 스크롤과 가로 회전이 충돌하지 않음
- 포인터 취소·모달 닫기·탭 전환 후 `grabbing` 상태가 남지 않음
- 아이템 착용 즉시 현재 각도에 맞는 프레임이 보이고, 지원 등급이 내려갈 때 설명이 나옴
- 정면 전용 조합에서 후면 버튼이 조용히 실패하지 않고 이유를 알려줌

### 접근성 QA

- 키보드만으로 0°→180°→0° 이동 가능
- VoiceOver/TalkBack에서 현재 방향과 착장 이름 확인 가능
- 200% 확대와 고대비에서도 버튼이 잘리지 않음
- reduced-motion에서 관성과 자동 회전이 없음
- 자동 회전 중 포커스 진입 시 즉시 정지

### 화면 크기

- 390px 모바일
- 834px 태블릿
- 1440px 데스크톱
- 기존 `docs/DESIGN_QUALITY_GUARDRAILS.md`의 인벤토리 카드 및 닭장 80~110px 축소 화면도 회귀 확인

## 완료 정의

다음 질문에 모두 “예”일 때만 360° 기능을 출시한다.

- 백팩을 착용하고 후면 180°에서 가방 전체와 어깨 접촉부를 확인할 수 있는가?
- 정면·측면·후면이 서로 다른 실제 제작 자산인가?
- 어떤 경로에서도 `flip`, `scaleX(-1)`, `rotateY()`로 없는 뒷면을 만들지 않는가?
- 16각도 중 하나라도 누락되면 자동으로 정면 전용으로 안전하게 내려가는가?
- 마우스 없이 키보드와 터치로도 앞·뒤를 볼 수 있는가?
- 세로 스크롤, 브라우저 확대, reduced-motion을 침해하지 않는가?
- 로드 실패 시 깨진 이미지나 빈 캐릭터 대신 마지막 정상 프레임 또는 정면 자산이 보이는가?
- 모든 공개 조합이 `DESIGN_QUALITY_GUARDRAILS.md`의 90점 기준을 통과했는가?

하나라도 아니오라면 기능 이름에 “360°”를 사용하지 않고 `정면 미리보기` 또는 `앞/뒤 미리보기`로 표기한다.
