# Home 검색·퀵슬롯 UI 감사 및 최소 변경안

## 결론

현재 홈 화면이 복잡해 보이는 직접 원인은 검색 진입점이 세 곳에 중복되고, 퀵슬롯이 홈 첫 번째 대형 카드로 삽입되기 때문입니다.

현재 검색 진입점은 다음 세 가지입니다.

1. 전역 고정 돋보기 `#homeSearchBtn`
2. 홈 대시보드의 `🔎 검색` 칩
3. 대형 `home-quick-dock` 내부의 상시 노출 검색창

요청한 구조는 기존 고정 돋보기를 유일한 진입점으로 남기고 다음 상태로 단순화하는 것이 가장 안전합니다.

- 기본: 돋보기 아이콘만 표시
- 클릭: 오른쪽 기준으로 검색 입력창이 왼쪽으로 확장
- 확장 상태: 입력창 아래 작은 퀵슬롯 팝업 표시
- 빈 슬롯: 설명문 대신 작은 점선 칸과 `+` 표시
- `+` 클릭: 기존 기능 선택기를 열어 슬롯 추가

데이터 저장, 권한 필터, 검색 엔진은 그대로 두고 UI 조립부만 바꾸면 됩니다.

## 현재 간섭 원인

### 1. 퀵슬롯이 홈의 대형 첫 카드로 강제 삽입됨

파일: `assets/presence-home-quickslots.js`

- `ensure()`가 `#m-home .wrap`의 첫 자식으로 `section.home-quick-dock`을 삽입합니다.
- 이 섹션에는 제목, 편집 버튼, 상시 노출 검색창, 슬롯 영역이 모두 포함됩니다.
- 빈 상태에서도 설명문과 큰 `＋ 기능 추가` 버튼이 출력되어 화면을 많이 차지합니다.
- `ensure()`가 주기적으로 다시 호출되므로 DOM이 사라질 경우 대형 카드가 다시 생성됩니다.

파일: `assets/presence-avatar-studio.css`

- `.home-quick-dock`에 큰 패딩, 테두리, 배경, 그림자, 하단 여백이 적용됩니다.
- 홈 보조 기능이어야 할 퀵슬롯이 핵심 콘텐츠 카드처럼 보입니다.
- 모바일에서도 카드 구조가 유지되어 작은 화면에서 더 큰 비중을 차지합니다.

### 2. 기존 돋보기와 신규 검색창이 동시에 존재함

파일: `index.html`

- `#homeSearchBtn`은 `position: fixed`인 전역 돋보기입니다.
- `hsInit()`에서 버튼과 전체 화면 검색 모달을 생성합니다.
- 후반 CSS가 `display:flex!important`를 강제하여 홈 외 탭에서도 계속 보일 수 있습니다.
- `goTab()` 역시 탭 전환 때마다 버튼을 다시 표시합니다.
- 모바일 규칙에서 `top`과 `bottom`이 동시에 남을 수 있어 위치 계산이 불안정합니다.
- `renderHomeDash()`에는 별도의 `🔎 검색` 칩도 있습니다.

결과적으로 사용자는 같은 기능으로 보이는 버튼과 입력창을 여러 개 보게 되고, 고정 돋보기와 대형 카드가 시각적으로 간섭합니다.

### 3. 빈 슬롯이 실제 슬롯처럼 보이지 않음

파일: `assets/presence-home-quickslots.js`

- 현재 `render()`는 빈 상태 안내문을 먼저 보여줍니다.
- 슬롯 추가는 별도 텍스트 버튼으로 표시됩니다.
- 사용자가 기대한 “빈 퀵슬롯 칸에 `+`가 있는 형태”가 아닙니다.

## 최소 변경 지점

### A. 기존 돋보기를 단일 진입점으로 사용

파일: `index.html`

1. `#homeSearchBtn`은 유지합니다.
2. 클릭 동작을 `hsOpen()` 직접 호출에서 `toggleHomeQuickLauncher()` 호출로 바꿉니다.
3. `hsOpen()`, `hsSearch()`, `hsGo()`, `hsGoUser()`는 검색 처리용으로 유지합니다.
4. `renderHomeDash()`의 중복 `🔎 검색` 칩은 제거합니다.
5. `goTab(name)`에서 검색 버튼을 홈 탭에서만 보이게 합니다.

권장 조건:

```js
homeSearchBtn.style.display = name === 'home' ? 'flex' : 'none';
```

단, 현재 `display:flex!important` 규칙이 인라인 `display:none`을 이길 수 있으므로 해당 `!important` 강제 규칙도 제거하거나 홈 활성 상태 클래스를 기준으로 다시 작성해야 합니다.

### B. 대형 홈 카드 대신 작은 런처 생성

파일: `assets/presence-home-quickslots.js`

`ensure()`의 변경 범위만 최소화합니다.

- `#m-home .wrap` 첫 자식에 대형 섹션을 삽입하지 않습니다.
- `document.body`에 기존 돋보기 옆에 붙는 소형 `#homeQuickLauncher`를 한 번만 생성합니다.
- 닫힌 상태에서는 런처 본체를 감추고 돋보기만 표시합니다.
- 열린 상태에서는 검색 행과 아래 퀵슬롯 팝업만 표시합니다.

권장 구조:

```html
<div id="homeQuickLauncher" class="home-quick-launcher" aria-hidden="true">
  <div class="hql-search-row">
    <input id="hqdSearch" type="search" placeholder="무엇을 찾을까요?">
  </div>
  <div class="hql-popover">
    <div id="homeQuickSlots" class="hqd-slots compact"></div>
  </div>
</div>
```

`runHomeQuickSearch()`는 우선 그대로 재사용할 수 있습니다. 입력값을 기존 검색 모달로 넘기는 현재 동작을 유지하면 검색 로직 회귀 위험이 가장 낮습니다. 추후 검색 결과까지 작은 팝업 안에 넣고 싶다면 별도 단계에서 `hsSearch()` 결과 렌더러만 분리합니다.

### C. 빈 슬롯을 작은 `+` 셀로 렌더링

파일: `assets/presence-home-quickslots.js`

`render()`의 데이터 처리부는 유지하고 출력만 바꿉니다.

- 저장된 슬롯: 작은 아이콘과 짧은 라벨
- 남은 자리: 점선 테두리의 빈 셀
- 첫 빈 셀 중앙: `+`
- 설명형 빈 상태 문구와 큰 `＋ 기능 추가` 버튼: 제거
- `maxSlots = 8`, 중복 방지, 권한 필터, 저장 방식: 유지

최소안은 빈 셀 한 개만 `+`로 보여주는 것입니다. 전체 수용량을 더 직관적으로 보여주려면 8칸 전부을 렌더링하되, 비어 있는 모든 칸은 동일한 점선 스타일을 쓰고 첫 빈 칸만 활성화합니다.

### D. 기능 선택기는 기존 모달을 유지

파일: `assets/presence-home-quickslots.js`

- `quickslotModal`, `openPicker()`, 저장 로직은 그대로 유지합니다.
- 작은 팝업의 `+`가 기존 선택 모달을 열게 연결합니다.
- 이 방식은 UI 구조만 작게 만들면서 기존 슬롯 추가 기능을 보존하는 최소 변경입니다.

선택기까지 작은 팝오버로 바꾸는 것은 2차 개선으로 분리하는 편이 안전합니다.

### E. CSS를 카드형에서 확장형 런처로 교체

현재 위치: `assets/presence-avatar-studio.css`

권장 위치: 신규 `assets/presence-home-quickslots.css`

최소 변경만 원하면 기존 퀵슬롯 CSS 블록을 다음 원칙으로 교체합니다.

- 닫힘: 돋보기 42px만 보임
- 열림: 우측 고정 기준, 너비 약 300~340px로 왼쪽 확장
- 팝업: 검색창 바로 아래, 작은 그림자와 둥근 테두리
- 슬롯: 데스크톱 4열, 모바일 3열
- 슬롯 셀: 약 52~64px, 작은 아이콘과 한 줄 라벨
- 팝업의 `z-index`: 일반 콘텐츠보다 높고 전체 화면 모달보다 낮게
- 모바일: `top`과 `bottom` 중 하나만 사용
- 하단 내비게이션과 safe area를 침범하지 않도록 모바일은 하단 기준 배치

애니메이션은 `width`, `opacity`, `transform`만 사용하고 레이아웃 전체를 밀지 않게 합니다.

## 권장 상태 모델

| 상태 | 화면 | 동작 |
|---|---|---|
| `closed` | 돋보기만 | 클릭 시 `open` |
| `open` | 옆으로 확장된 검색창 + 아래 퀵슬롯 | Enter 검색, 슬롯 실행, `+` 추가 |
| `picking` | 기존 기능 선택기 | 선택 후 저장하고 `open` 복귀 |

추가 동작:

- 바깥 영역 클릭: `closed`
- `Escape`: `closed`
- 홈 외 탭 이동: 닫고 숨김
- 열릴 때: 검색 입력창 포커스
- 버튼: `aria-expanded`, `aria-controls` 갱신

## 유지해야 할 기존 로직

다음은 수정하지 않는 것이 안전합니다.

- 슬롯 정규화 `clean()`
- 사용자별 로컬 저장 키
- Firebase 저장 및 불러오기
- 역할별 기능 노출 `visible()`
- 최대 슬롯 수 `maxSlots = 8`
- 기존 검색의 실제 이동·사용자 검색 처리
- 기능 선택기 데이터 목록

## 주기 실행 주의

현재 초기화가 주기적으로 실행되므로 `ensure()`는 다음 조건을 지켜야 합니다.

- 런처가 이미 있으면 다시 만들지 않음
- 사용자가 입력 중일 때 값을 초기화하지 않음
- 열린 상태를 임의로 닫지 않음
- 포커스를 다시 빼앗지 않음
- 렌더링은 슬롯 데이터가 바뀐 경우에만 수행

가능하면 4초 간격 재확인은 제거하고 홈 탭 진입, 로그인 사용자 변경, 슬롯 저장 완료 시점에만 갱신하는 편이 좋습니다. 다만 이는 최소 변경 범위를 넘어가므로 2차 최적화로 분리할 수 있습니다.

## 검수 체크리스트

- 홈 최초 진입 시 대형 퀵슬롯 카드가 보이지 않는다.
- 평소에는 돋보기 하나만 보인다.
- 돋보기를 누르면 검색창이 왼쪽으로 자연스럽게 확장된다.
- 검색창 아래에 작은 퀵슬롯 팝업이 붙어 보인다.
- 빈 상태에서도 안내문 대신 `+` 빈 슬롯이 보인다.
- `+`를 누르면 기존 기능 선택기가 정상적으로 열린다.
- 저장된 슬롯이 새로고침 뒤에도 복원된다.
- 권한 없는 기능은 슬롯에 표시되지 않는다.
- 같은 슬롯이 중복 저장되지 않는다.
- Enter 검색 시 입력한 문구가 그대로 검색된다.
- 바깥 클릭과 `Escape`로 닫힌다.
- 홈을 벗어나면 돋보기와 팝업이 숨겨진다.
- 모바일에서 하단 내비게이션, 상단 알림, 사용자 메뉴와 겹치지 않는다.
- 데스크톱·태블릿·모바일에서 검색창이 화면 밖으로 잘리지 않는다.
- 홈 대시보드에 중복 `🔎 검색` 칩이 남지 않는다.

## 구현 우선순위

1. 대형 `home-quick-dock` 삽입 제거
2. 기존 돋보기를 단일 토글로 연결
3. 확장 검색창과 작은 슬롯 팝업 생성
4. 빈 슬롯을 `+` 셀로 변경
5. 홈 탭 범위 제한 및 중복 검색 칩 제거
6. 모바일 위치 충돌과 접근성 검수

이 순서라면 사용자 데이터와 검색 기능을 건드리지 않고도 요청한 외형과 상호작용으로 바꿀 수 있습니다.
