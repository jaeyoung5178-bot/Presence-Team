# Avatar Studio 공개 카탈로그 시각 QA

최종 점검: 2026-07-18  
범위: `assets/presence-avatar-studio.js`, `assets/presence-avatar-studio.css`, `assets/pets/`의 공개 의상·머리·소품 원화  
목적: 이름만 다른 중복 코스튬, 캐릭터와 따로 노는 착장, 모바일 카드 품질 저하를 배포 전에 차단한다.

## 결론

현재 작업본은 **같은 원화를 색상 이름만 바꿔 수십 개로 늘리던 문제는 제거했다.** 공개 카탈로그는 의상 4종, 머리 3종, 놀이 소품 2종의 총 9개 독립 항목으로 줄었고, 같은 `artKey`를 중복 등록하거나 CSS 필터 복제본을 항목으로 만드는 경우 QA가 실패하도록 바뀌었다.

그러나 공개 가능한 시각 품질은 아직 통과가 아니다. 의상과 머리를 함께 착용할 때 사용하는 완성 마스터 12장 중 11장에 밝은 초록색 크로마키 사각형이 남아 있으며, 캐릭터의 얼굴·몸 비율과 광원도 조합마다 달라 한 캐릭터의 코디로 보이지 않는다. 비치볼과 튜브는 캐릭터 앞에 놓는 단일 레이어라 날개와 소품 사이의 앞뒤 가림 및 접촉 표현이 없다. 이 상태에서 9개 전부를 공개하면 중복 문제는 해결되어도 사용자가 지적한 `붙여 놓은 느낌`은 남는다.

| 항목 | PASS 기준 | FAIL 예시 |

## 현재 PASS

1. **이름만 다른 중복 항목 제거**  
   현재 `addUniqueItems()`는 원화 한 장당 카탈로그 항목 하나만 만든다. 공개 항목은 의상 4 + 머리 3 + 소품 2 = 총 9개다.

2. **중복 회귀 방지 검사 추가**  
   `scripts/qa-audit.mjs`가 동일 `artKey` 중복과 `filter !== 'none'`인 필터 복제 항목을 실패 처리한다.

3. **미검수 분리형 액세서리 비공개**  
   무기·등·목·손목·발·허리 아이템은 `file === 'accessory'`로 구분되어 공개 목록에서 제외된다. 숫자를 늘리기 위해 품질 미달 아이템을 노출하지 않는 방향은 맞다.

4. **기본 크롭 방지 구조**  
   카드와 대형 스테이지는 `object-fit: contain`과 정사각형 좌표계를 사용하므로 원본 자체가 깨끗하다면 캐릭터 잘림 위험은 낮다.

5. **의상+머리 조합의 통합 마스터 우선**  
   의상과 머리를 동시에 고르면 분리 레이어를 얹지 않고 `presence-fitted-{body}-{head}.webp` 한 장을 사용한다. 렌더링 전략 자체는 일체감 확보에 적합하다.

## 현재 FAIL 목록

### P0 — 공개 차단이 필요한 문제

1. **완성 마스터 12장 중 11장에 초록 크로마키 배경이 남음**  
   수동 원화 점검 결과 `presence-fitted-raincoat-shades.webp`를 제외한 나머지 완성 마스터에서 불투명 또는 반투명 초록 사각형과 초록 계단형 테두리가 보인다. 투명 배경 파일이라는 메타데이터만으로는 통과할 수 없다.

2. **한 캐릭터의 코디가 아니라 조합마다 캐릭터 자체가 바뀜**  
   `raincoat-shades`, `leader-wig`, `floral-straw`, `swimsuit-shades`를 비교하면 눈 크기·얼굴 폭·몸통 비율·날개·발 위치·광원이 서로 다르다. 의상만 바뀌는 코디 시스템이 아니라 서로 다른 완성 캐릭터를 교체하는 인상이다.

3. **놀이 소품 2종이 신체 접촉·가림을 표현하지 못함**  
   `presence-item-ball.webp`와 `presence-item-tube.webp`는 캐릭터 위에 한 장으로 얹힌다. 날개가 소품 앞뒤를 잡는 마스크나 조합 전용 마스터가 없어 실제로 들거나 착용한 느낌을 보장할 수 없다.

4. **카탈로그 설명이 실제 품질보다 강하게 약속함**  
   `체형 기준점에 맞춘 일체형 의상`, `날개 위치에 맞춘 놀이 소품`이라는 문구는 현재 초록 배경과 소품 접촉 실패 상태를 통과한 것처럼 보이게 한다. 실제 자동 캡처 QA를 통과하기 전에는 이런 확정형 설명을 쓰면 안 된다.

### P1 — 출시 전 수정이 필요한 문제

5. **마스터 캔버스 규격 불일치**  
   `presence-fitted-raincoat-shades.webp`만 640×640이고 다른 완성 마스터는 418×418이다. `contain`으로 화면 크기는 맞아도 얼굴·바닥선·여백·축소 선명도가 일관되지 않는다.

6. **색상·털 모양과 완성 의상이 공존하지 못함**  
   사용자가 색상 또는 털 모양을 선택하면 현재 의상과 머리 프리셋을 해제한다. 선택 반응이 보이는 안전장치이지만, 사용자는 원하는 색·털·의상을 조합하는 시스템으로 이해하므로 커스터마이징 기대와 다르다. 완성 마스터가 기본 허니·클래식 외 변형을 지원하지 않는 구조적 한계다.

7. **모바일 카드의 텍스트와 터치 영역이 작음**  
   421~767px에서 두 열·126px 미리보기를 사용하고 이름 12px, 설명 9px, 버튼 10px이다. 색상 스와치는 38×38px이고 색 이름은 8px로 버튼 아래에 배치된다. 일반 모바일 가독성·44px 터치 기준을 통과하지 못한다.

8. **색상 이름이 스크롤 영역에서 잘릴 가능성**  
   색 이름은 스와치의 아래쪽 `-18px`에 놓이지만 스크롤 컨테이너의 아래 패딩은 7px뿐이다. 모바일과 브라우저별 overflow 처리에서 이름이 잘리거나 거의 보이지 않을 수 있다.

9. **축소 닭장 뷰가 별도 검수되지 않음**  
   닭장에서는 82×90px로 축소하고 복잡한 소품을 일부 숨긴다. 하지만 12개 통합 마스터와 2개 소품에 대한 축소 캡처 비교 결과가 없고, 초록 배경은 이 크기에서도 사각형으로 보인다.

### P2 — 회귀 방지를 위한 보완

10. **원화 픽셀 중복·배경 오염을 자동 검출하지 않음**  
    현재 QA는 카탈로그의 `artKey`와 필터 중복은 잡지만, 서로 다른 파일명이 실제로 같은 이미지인지, 초록 픽셀이 일정 비율 이상 남았는지, 캔버스 크기가 다른지는 검사하지 않는다.

11. **조합별 스냅샷 기준 이미지가 없음**  
    의상 4 × 머리 3 = 12개 조합과 소품 2개, 390/768/1440px, 82×90px 축소 뷰를 비교할 기준 이미지가 없다. 코드가 통과해도 시각 회귀를 막을 수 없다.

## 공개 권장 상태

- **즉시 공개 가능:** 기본 병아리 색상 12종과 털 8종 중 실제 클릭·저장·새로고침·축소 뷰가 확인된 항목만.
- **조건부 공개:** 단독 의상 4종과 단독 머리 3종은 배경 투명도와 동일 캐릭터 기준점을 개별 검수한 뒤 공개.
- **현재 공개 중단 권장:** 초록 크로마키가 남은 의상+머리 완성 마스터 11종, 접촉 마스크가 없는 비치볼·튜브.
- **계속 비공개:** 무기·등·목·손목·발·허리 분리형 액세서리. 다각도 원화와 신체 접촉면 QA를 통과하기 전에는 이름이나 개수만 늘리지 않는다.

## 다음 배포의 최소 합격선

1. 12개 완성 마스터를 동일한 캐릭터 리그, 418×418 캔버스, 동일 바닥선으로 다시 제작한다.
2. 초록 픽셀·불투명 배경·비정상 캔버스 크기를 자동으로 실패시키는 원화 검사기를 추가한다.
3. 비치볼과 튜브는 날개 앞/뒤 마스크를 가진 조합 마스터로 만들거나 검수 완료 전까지 숨긴다.
4. 390/430/768/1440px 및 닭장 82×90px 스냅샷을 생성해 사람 검수에서 한 장이라도 `붙인 느낌`이 나면 배포를 중단한다.
5. 모바일 이름·설명·버튼을 최소 14/12/14px, 터치 영역 44px 이상으로 올린다.
